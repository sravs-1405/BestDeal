# BestDeal

BestDeal compares Google Shopping India listings with an explainable Python ranking pipeline. Listing facts are kept separate from recommendations: unavailable price, rating, shipping, delivery, COD and discount fields remain unknown. Search and price history use SQLite. Demo data is labelled and must not be treated as a live offer.

## Requirements

- Windows 10/11
- Node.js 22.13 or newer (`node --version`)
- Python 3.10 or newer (`py --version`)
- PowerShell

## Windows setup

1. Open PowerShell in the project folder.
2. Configure the backend:

   ```powershell
   cd backend
   Copy-Item .env.example .env
   notepad .env
   ```

3. Set SERPAPI_KEY for live Google Shopping India listings. Set a long random JWT_SECRET. For labelled sample listings without a SerpApi key, keep DEMO_MODE=true; set DEMO_MODE=false to search live listings. Google Shopping returns the offers it has indexed for a query, not every product from every retailer; COD, delivery and other details are shown only when the listing provides them.
4. Install and start the backend:

   ```powershell
   npm install
   py -3 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r python_ml\requirements.txt
   npm start
   ```

   The Python pipeline uses only the standard library. `PYTHON_PATH` may be set to `.venv\Scripts\python.exe` if the `python` command does not resolve to the virtual environment. The API listens on `http://localhost:5000` by default.

5. In a second PowerShell window, install and run the frontend:

   ```powershell
   cd frontend
   npm install
   npm run dev
   ```

   Open the local URL printed by Vite. Its `/api` requests proxy to port 5000. For a production build, run `npm run build` in `frontend`; the backend serves `frontend/dist` when it exists.

## Tests and ranker training

Run the ranking tests:

```powershell
cd backend
python -m unittest discover -s python_ml\tests -v
```

Run the HTTP API exercise in demo mode after dependencies are installed:

```powershell
$env:DEMO_MODE = 'true'
$env:JWT_SECRET = 'local-test-secret-change-this'
node tests\api-demo.test.js
```

Collect survey votes from the **Help improve BestDeal** page. Each pair uses saved live listing snapshots. After at least 30 votes, train and save learned weights:

```powershell
cd backend
python python_ml\train_ranker.py
```

The trainer prints agreement against the votes for its logistic ranker, always choosing the cheaper product, and always choosing the higher-rated product. `ranker.json` is generated locally and ignored by Git. The ranking pipeline blends it with default weights from 30 to 150 votes.

## API overview

- `GET /api/health`, `GET /api/categories`, `GET /api/search`, `GET /api/history`
- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`
- `GET|POST|DELETE /api/wishlist`
- `GET|POST|DELETE /api/comparisons`
- `GET /api/survey/pair`, `POST /api/survey/vote`

Search cache defaults to 12 hours (`CACHE_TTL_HOURS`). SQLite is stored under `backend/data/bestdeal.sqlite` by default; set `DATA_DIR` to choose another directory.

## Render deployment

The root `Dockerfile`, `.dockerignore`, and `render.yaml` define a single public Render web service. The image builds the React frontend, includes the Node API and Python ranking script, and configures `/api/health` as the health check. Connect this repository to Render as a Blueprint and set `SERPAPI_KEY` when Render prompts for it; never commit the key or add it to `render.yaml`. `JWT_SECRET` is generated by Render.

The Blueprint uses Render's free web-service plan. Free services spin down after 15 minutes without traffic, so the first visit after idle can take about a minute. The free filesystem is ephemeral: SQLite accounts, wishlist, comparisons, votes, price history, and search cache can be lost when the service restarts, spins down, or redeploys. Persistent disks require a paid service. Do not use this free SQLite setup for durable customer accounts; use a persistent database or paid storage before relying on it for production user data.

## Limitations

- Google Shopping currently returns a fixed page of roughly 40 offers per query; num and start do not expose a complete retailer catalogue. BestDeal combines and deduplicates the main, categorized and inline offers it receives. COD, delivery and other absent details stay “not listed.”
- Price history starts empty and grows only from live searches, with snapshots limited to one per product per six hours.
- Hindi and Telugu translations are starter translations and need native-speaker review.
- Sample listings in `DEMO_MODE` are for rehearsal and are explicitly labelled.
